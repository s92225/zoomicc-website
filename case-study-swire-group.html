The pain point

The team had the information. The risk was losing context between systems.

Line to Take emails and SharePoint incident files already carried useful response material. The challenge was turning changing incident updates into reliable knowledge records without losing source, status, or system ID context.

01 / Intake

Email and files did not match

Line to Take emails and SharePoint incident folders arrived with different structure and review timing.

02 / Publishing

Active status mattered

Only active items should reach the knowledge base; inactive material still needed a clean internal note.

03 / Audit

Trace IDs had to survive

Collection IDs and chunk IDs needed to return to Excel so every answer could be traced to the original incident row.

The Flow2 solution

Flow2 kept the three automation paths, but made the operating model understandable.

The build still uses three flows: email intake, incident upload, and direct chunk creation. The user-facing model is simpler: capture the update, clean it with AI, decide active vs reference, publish the useful record, then write the trace ID back.

Flow A

Email becomes a logged note

AI structures the Line to Take email, creates a markdown note in SharePoint, and logs the record in Excel.

Flow B

Incident rows are reviewed

Each row is cleaned, dated, classified active or inactive, and uploaded only when it should become live knowledge.

Flow C

Chunks publish directly

Where the file handoff is unnecessary, the workflow creates UAT knowledge chunks and writes the chunk ID back to Excel.

The outcome

The result: knowledge records that are publishable and traceable.

Swire Group gets a cleaner path from incident material to knowledge-base content. The team can see what came in, how AI prepared it, whether it was published, and which Excel ID proves the source.
